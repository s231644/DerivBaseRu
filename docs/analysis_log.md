## Метод

1. Просев по словарям (`filter_by_dictionaries.py filter`): запись держится, если слово есть
   в Викисловаре с нужной частью речи либо встречается у Даля (заголовок или токен толкования).
2. Записи, подтверждённые **только Далей**, уходят в `--doubtful` и проверяются:
   - группа 1 (499 шт.) — **субагентами** (`dahl-judge-1/2`: 212 + 165 одобрено);
   - группы 3–5 — субагентами не масштабируется: слова, известные Викисловарю **с другой
     частью речи**, отбрасываются сразу; остальные проверяются морфологически (`pymorphy3`, `ADVB`).
3. Дочистка (`filter_by_dictionaries.py clean`): убираются слова с заглавной буквы
   (`заМало ← Малый`, `вполБега ← Бег`) и латиница; битые строки пропускаются.

## Как воспроизвести

```sh
# генерация наречий (цепочка: сгенерированные числительные как доп. вход)
.venv/bin/python scripts/run_pipeline.py --pos-a adv --complexities simple,complex \
    --extra-dataset data/derived/num.jsonl --out data/derived/adv.jsonl.gz

# compound-правила с фиксированным префиксом (модификатор pos_m="*" берётся из имени правила)
.venv/bin/python scripts/run_pipeline.py --pos-a adv --complexities compound \
    --exclude-rules "rule1026*,rule981*" --modifier-limit 1 --out /tmp/adv_compound.jsonl.gz

# просев по словарям (пример: группа 3)
.venv/bin/python scripts/filter_by_dictionaries.py filter \
    --rules-prefix rule982,rule977,rule981,rule979,rule985,rule987,rule986,rule983,rule980 \
    --pos-a adv --input data/derived/adv.jsonl.gz \
    --out data/derived/adv_g1.jsonl --doubtful /tmp/g1_doubtful.jsonl

# слияние вердиктов субагентов
.venv/bin/python scripts/filter_by_dictionaries.py merge \
    --filtered data/derived/adv_pfx.jsonl \
    --judged /tmp/dahl_ok1.jsonl --judged /tmp/dahl_ok2.jsonl \
    --final data/derived/adv_pfx.final.jsonl

# дочистка
.venv/bin/python scripts/filter_by_dictionaries.py clean \
    --input data/derived/adv_g1.final.jsonl --out data/derived/adv_g1.final.clean.jsonl
```

## Инструменты

- `scripts/run_pipeline.py` — генерация: `--extra-dataset` (цепочки), `--exclude-file` (псевдо-леммы),
  `--exclude-rules` (пропуск правил), `--real-only`, поддержка фиксированных префиксов в compound-правилах.
- `scripts/filter_by_dictionaries.py` — `filter` (словари + doubtful), `merge` (вердикты субагентов), `clean` (артефакты).
- `scripts/sort_edges.py` — группировка по частоте правила и сортировка записей.
- `docs/verification_policy.md` — де-факто важнее устаревшей грамматики; диалектное и устаревшее подходит.

## Наблюдения

- Продуктивность падает от простых типов к сложным: суффиксальные от прилагательных дают тысячи
  подтверждений, префиксально-суффиксальные — сотни, compound — десятки.
- Ядро: `adj + о/и` (6 017 в группе 3), `в + noun + ACC` (410 в группе 4), `в + [пол] + noun + GEN` (57 в группе 5).
- Лучшие по точности: `не + adv` (7.08%), `-онько` (2.38%), `-ком` (2.65%), `-овато` (2.00%).
- `rule982(noun + INSTR)`: 787 324 рёбер, но подтверждается лишь ~0.05% — тип лексически ограничен.
- Compound-правила с `pos_m: "*"` (фиксированный префикс `[полу]`, `[пол]`, `[три]`) движок до
  сегодняшнего дня вообще не порождал — добавлена поддержка в пайплайне.
- Остаточный шум: Dahl-токенные совпадения (`набедно ← бедный`), формы с заглавной буквы (уже отсеяны),
  редкие склейки (`вполздорова ← здоровый`).

## Префиксы-модификаторы больше не узлы графа (15:10)

У compound-правил с фиксированным модификатором (`compound_rules.modifiers[].pos_m == "*"`)
первый компонент берётся из имени правила (`[полу]`, `[мимо/само]`, `в + [пол]`, `в + [пол/три]`),
и раньше он попадал в запись как отдельный родитель — из-за этого в графе появлялся узел-хаб
«полу», склеивающий разные лексические семьи (`полусидя` и `полулёжа` через общий «полу»).

Теперь для таких правил запись содержит **одного родителя — лексему-основу**, а сам префикс
пишется в поле `affix`, `kind: "pfx"`:

```json
{"word": "полубоком", "pos": "adv", "kind": "pfx", "affix": "полу",
 "parents": [{"word": "боком", "pos": "adv", "role": "head", "slot": 0}]}
```

Так держится цепочка дерева деривации: `сидеть → сидя → полусидя`, `лежать → лёжа → полулёжа`
(разные графы), без общего узла «полу». Проверено на группе 5: 74 записи, узлов-префиксов — 0.

Фиксированные префиксы задокументированы в самих правилах полем `fixed_affix`:
`adv=compound.json` (`полу`, `мимо/само`, `впол`, `впол/втри`), `noun=compound.json` (`пол`),
`verb=compound.json` (`полу/само`, `фицировать`).

## Rare-таблицы в compound-голове (15:16)

`rule1027([мимо/само] + verb + ом -> adv)` долго давал 0 рёбер: его голова —
`rule986(verb + ом/ком -> adv)`, у которой **нет подправил, только rare-таблица**
(`мелькать -> мельком`, `кувыркаться -> кувырком`). Пайплайн вызывал compound без
`use_rare`, поэтому голова не образовывалась. Применение частей вынесено в
`apply_compound_rule()` (напрямую, с `use_rare`), из-за чего правило заработало:

```
ходить + мимо -> мимоходом, мимоходуном      ездить + мимо -> мимоездом
ходить + само -> самоходом                   ездить + само -> самоездом
катить + само -> самокатом                   лететь + мимо -> мимолётом
плыть  + само -> самоплавом                  учиться + само -> самоуком
```

Итог группы 5: **81** запись (полу 23, впол 41, впол/три 10, мимо/само 7),
все `kind: pfx`, узлов-префиксов в графе — 0.

## Открытые задачи (15:27)

1. **Мусорные рёбра** (`раб -> араб`): ищем связи, где деривация случайна. Равноправные деривативы
   (одно слово от двух разных основ, напр. `закруглённо <- закруглённый` и `<- круглённый`) — норма,
   их не трогаем.
2. **Многокорневые компоненты** — следствие незавершённости цепочек: `круг -> круглый -> круглённый`
   (ребро `круг -> круглый` относится к датасету прилагательных, которого ещё нет). Нужны датасеты
   остальных частей речи, чтобы предки доходили до истинного корня.
3. Инструмент проверки: `scripts/validate_components.py` (режимы `report` и `blacklist`).

## Мусорные рёбра и blacklist (15:40)

Проверка 9 492 чистых записей: 8 130 подтверждены Викисловарём как наречия, 185 — заголовком
Даля, **1 080 «слабых»** (совпадение лишь токеном в толковании Даля; с нормализацией ё/е),
85 — слово есть в Викисловаре, но с другой частью речи.

Слабые разданы четырём субагентам по 270 записей: **одобрено 236 + 207 + 168 + 260 = 871**,
отклонено 209. Наблюдения субагентов: `rule1020(в/на + verb)` почти целиком мусорное (99 из 111
отклонено — это отглагольные существительные), `rule982(noun + INSTR)` даёт много наречий
творительного падежа, часть которых реальна (диалектные: `аредом`, `кобеняком`), а часть —
случайные формы (`гзом <- гез`, `двом <- дев`).

Отклонённые рёбра и 85 записей с чужой ЧР сведены в артефакт **`data/junk_blacklist.jsonl`**
(212 записей). Применение — режимом `blacklist` в `scripts/filter_by_dictionaries.py`.

Итог после чистки: **9 190 наречий** (adv_pfx 1 155, adv_sfx 377, adv_g1 6 371, adv_g2 1 209,
adv_g5 78) + 98 числительных.

Побочный случай: применение blacklist «на месте» (`--input X --out X`) обнулило пять файлов,
т.к. инструмент открывал выход до чтения входа. Инструмент исправлен (вход читается целиком
до записи), файлы восстановлены полной цепочкой (merge -> проверка ЧР -> clean -> blacklist).

## Сверка написаний ё/е и потерянные родители (15:55)

Замечание Даниила: не видно пар `густо -> густенько`, `рано -> ранёхонько`. Разбор:

1. **Потерянные родители.** В группе 2 (`adv_sfx`) у 374 из 377 записей поле `parents` было пустым —
   их записал первый вариант скрипта. В графе такие наречия оказывались изолированными узлами.
   Файл перегенерирован: **382 записи, все с родителями** (`грустенько <- грустно` и т.п.).
2. **Написание ё/е.** Правила дают `-ехонько/-ешенько` и `-енько`, а словарная норма часто с «ё»
   (`ранёхонько`, `густёхонько`, `ранёшенько`). Нормализация в инструменте не сворачивала ё к е,
   поэтому такие формы не находились поиском. Исправлено: `norm()` теперь считает ё и е одной буквой,
   добавлен режим `canonical` — написание приводится к словарному (`ранехонько -> ранёхонько`),
   а blacklist сопоставляется без учёта ё/е.

Следствие: ранее просев по словарям шёл с ё-чувствительным сравнением, поэтому часть форм могла быть
отброшена зря. После завершения текущей генерации глаголов группы 1–5 стоит перефильтровать
инструментом с исправленной нормализацией.

## Правило Xым-X (редупликация + суффиксация), § 981 (16:05)

«Русская грамматика» 1980, **§ 981**: «Характер наречных образований имеют формы с суф. -ым,
обозначающие тот же признак, что и мотивирующее прилагательное, но с оттенком усиления. Они
употребляются только препозитивно рядом с формами мотивирующих прилагательных (преимущественно
краткими) или с наречиями на -о: белым-бело, черным-черно, давным-давно, полным-полно».

Тип: **редупликация + суффиксация**. Состав закрытый, поэтому формы вынесены в rare-таблицу
(по данным Викисловаря). Правило добавлено в `derivbase_ru/rules/rus/adv/simple/adv=adj+ymX.json`:
`rule981(adj + ым-X -> adv)`, info SFX, со ссылкой на § 981.

Результат (`data/derived/adv_ymx.clean.jsonl`, 5 рёбер):
`белым-бело <- белый`, `давным-давно <- давний`, `темным-темно <- темный/тёмный`, `черным-черно <- чёрный`.

Не прошли фильтр, хотя attested: `полным-полно` и `располным-полно` — в разобранном Викисловаре
у них `pos: None` (парсер не распознал POS-шаблон страницы). Отдельная задача для парсера.
Также `раным-рано` есть в словаре как наречие, но мотивирующего прилагательного `раный` в корзине нет.

Добавлен ключ пайплайна `--include-rules` (отбор правил по префиксу имени).

## Аудит ё: почему пропадала связь `чёрный -> черно` (16:15)

- Правило `rule977(adj + о -> adv)` от «чёрный» даёт `чёрно` (**с ё**).
- В Викисловаре статья наречия — **`черно`** (без ё), а прилагательное — `чёрный` (с ё).
- Старый просев сравнивал написания **ё-чувствительно**, поэтому `чёрно` не находилось в словаре
  (`черно`) и запись **отбрасывалась**. В чистых файлах осталось всего 398 записей с ё из 9 200.

Доработка проверки:
1. `norm()` в `filter_by_dictionaries.py` теперь сворачивает **ё → е** (влияет и на просев, и на blacklist).
2. Режим `canonical` приводит написание к словарному (`чёрно -> черно`, `ранехонько -> ранёхонько`).
3. Новый режим **`yocheck`** — диагностика: сколько записей с ё и какие написания расходятся со словарём.

Восстановление: группы 1–5 нужно перефильтровать исправленным инструментом — тогда потерянные
ё-формы (в том числе `черно <- чёрный`) вернутся. Запускается после текущей генерации глаголов.
