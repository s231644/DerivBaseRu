# Актуальный реестр глаголов для генерации

Основной список — [`data/verbs_registry.tsv`](../data/verbs_registry.tsv),
машинная версия — [`data/verbs_registry.jsonl.gz`](../data/verbs_registry.jsonl.gz).
Обе версии содержат **46 895 типизированных лемм**, упорядоченных по алфавиту
(ё рядом с е), и собраны из одного снимка данных.

Многотипных лемм 143: у **91** подтверждены разные парадигмы, для **52**
неоднозначность пока не разрешена. Наличие нескольких типов не означает ошибку.
Автоматическое назначение одного типа также не означает ручную проверку леммы.

## Состав записи

- `word`, `pos`, `inflect_type` — лемма, часть речи и полный актуальный набор типов.
- `review_status` — автоматическое назначение, явное CSV-назначение, правило
  пользователя, LLM-решение, перенос от основы или нерешённый случай.
- `ambiguity` — `none`, `confirmed_variants` либо `unresolved`.
- `needs_review` — требует ли разрешения оставшаяся многотипность.
- `variants` — отдельные парадигмы: тип, инфинитив с ударением, при наличии
  форма 1-го лица и значение. Ударение не добавляется догадкой, если его нет
  в принятом решении. Например, у `спеть` хранятся `спе́ть → спе́ю` (1)
  и `спе́ть → спою́` (12петь).
- `inherited_from` — невозвратная основа, от которой скопированы типы.
  Механически образованные возвратные формы помечены как унаследованные;
  значение основы записано в `base_meaning`, а не объявлено значением рефлексива.
- `type_sources`, `notes` — основания назначения и пояснения.
- `generation_excluded` — лемма исключена действующим `pseudo_lemmas.txt`.
- `base_inventory_types`, `base_real` — сведения о заданной непроизводной
  или связанной основе из CSV. Омонимичные строки CSV объединены в этом поле.

Для `жать` сохранены обе основы CSV (14м/14н) в `base_inventory_types` и заметка
о том, что прежнее плоское назначение содержит только последнюю CSV-строку.
Экспорт не меняет назначения самовольно. Перечень включает типизированные
псевдоосновы, но их присутствие не отменяет исключения при генерации.
Глаголы, которым тип ещё не назначен, в этот список не входят.

## Использование при генерации

По умолчанию новый реестр читают:

- `scripts/rebuild_verb_prefixes.py`;
- `scripts/rebuild_verb_suffixes.py`;
- `scripts/run_pipeline.py` — для русских глагольных основ обычных правил,
  если не переданы свои `--inflect-types` или явный `--guesser`.

Старый `data/verb_inflect_types.json` сохранён как совместимая плоская карта.
`--inflect-types` принимает как её, так и новый JSONL(.gz). Общий загрузчик
проверяет схему, повторные леммы и непустые списки типов. Глаголы без назначения
в выбранном источнике не проходят обычные правила с неограниченным типом.

Текущий интерфейс движка получает объединение типов леммы. Акцентированные
записи сохраняются в реестре для различения омографов, но контекст значения
и ударения пока не используется для выбора одного типа внутри генерации.
Типы существительных/прилагательных и правила сложений этим изменением
не заменяются глагольным справочником.

## Обновление

```sh
# Собрать обе версии из текущих назначений и решений, без генерации кандидатов:
.venv/bin/python scripts/build_verb_registry.py
```

Экспорт проверяет согласованность LLM-решений и переноса от основ с текущими
типами. `docs/verb_registry_2026.json` хранит счётчики и SHA-256 входов/выходов.
Gzip собирается воспроизводимо без временной метки. Отдельно запускать
генерацию кандидатов для обновления реестра не требуется.

Полный сборщик `scripts/build_inflect_types.py` теперь также экспортирует реестр
после применения всех политик. Для исправлений меняются назначения/политики,
затем пересобираются обе версии; TSV и gzip не редактируются независимо.
