# Алгоритм фильтрации и проверки rule836

Основная проблема — не короткие основы, а чрезмерное число допустимых
изменений основы и смешение разных значений. В текущих данных **2820 пар**,
**2080 производных**, у **513** производных несколько родителей.

Например, правило предлагает:

- `копать`, `копировать`, `копить`, `коптеть`, `коптить` → `копнуть`;
- `мести`, `метать`, `метить`, `мечтать` → `метнуть`;
- `свергать`, `сверить`, `сверкать`, `свертеть`, `сверять` → `свернуть`.

У конкурирующих разборов могут совпадать строки основы, хотя значения разные.
Поэтому фиксированный порог длины или проверка одного inflect_type проблему
не решают. Одновременно короткие правильные основы нельзя отбрасывать.

## Предлагаемый порядок

### 1. Проверять допустимость конкретного разбора основы

Источник типов — актуальный `verbs_registry.jsonl.gz`. Для многотипной леммы
нужно проверять каждый вариант отдельно, сохраняя ударение и значение там,
где они известны. При неизвестном типе не включать неограниченное применение.
Соблюдать действующий список исключённых псевдолемм.

Форма цели должна соответствовать суффиксу -нуть/-нуться и допустимой
парадигме, но сама по себе парадигма с -ну- ничего не доказывает о мотивации.
Разборы pymorphy3 по аналогии не равны словарному подтверждению.

### 2. Сохранять и проверять последовательность преобразований

Для каждого кандидата полезно хранить номер case, исходную основу, удалённый
тематический суффикс, удалённый согласный и обратное чередование. Сейчас эта
информация в JSONL потеряна: есть только итоговая пара.

Нужны отдельные модели:

- продуктивные типы 1/4/5/6: убрать тематическую часть и присоединить -ну-;
- тип 2: удалять -ова-/-ева-/-ирова- только в соответствующей модели,
  не внутри произвольного корня;
- редкие типы: применять заданные типу преобразования инфинитивной основы;
- дополнительные сокращения корня: подтверждать конкретным гнездом или
  словарным отношением, а не разрешать всем optional-комбинациям одинаково.

Например, удаление -г- у `дёргать → дёрнуть` или `двигать → двинуть` реально.
Значит, общий запрет удаления согласного также неверен. Но одновременное
неподтверждённое усечение и обратное чередование должно отправлять разбор
в приоритетную проверку. Автоматически отклонять все такие пары нельзя.

### 3. Искать свидетельство именно отношения

Сильнее всего готовое проверенное решение или явное словарное соответствие
между этой парой. Использовать направленное поле `соотв` обеих статей и
прямое толкование через конкретный мотивирующий глагол. Синонимы, совместное
упоминание, общая часть строки и наличие обеих лемм слабее.

Даже словарное видовое соответствие не обязательно подтверждает именно
одноактное значение нужного -ну₂-. Оно даёт высокоприоритетный материал для
принятия, но механизм словообразования и омонимия суффикса проверяются отдельно.

Слова «однократно», «резко», «одним движением» помогают искать нужный смысл,
но не служат самостоятельным доказательством совпадения действий. Отсутствие
этих слов также не является поводом для отказа.

### 4. Проверять значения по всем конкурентам одного производного

Одна единица задания LLM — производное со всеми предполагаемыми родителями,
типами/ударениями, толкованиями обоих участников и разбором основы.
Решение возвращается **отдельно для каждой пары**, с указанием принятого смысла.
Правильный родитель не легализует остальных.

Критерии решения:

- сохраняются корневое действие, участники и направленность;
- одноактность/краткость/усиление объясняют различие между словами;
- при омонимии названы конкретные совместимые значения;
- значение изменения состояния не смешано с другим одноактным действием;
- отсутствие толкования не восполняется придуманным значением.

`accepted` — мотивированное отношение; `rejected` — установлено несовпадение
действия/корня/значения; `pending` — недостаточно данных. Словарная редкость,
разговорность и совершенный вид источника сами по себе не являются отказом.

### 5. Фильтрация и воспроизводимость

В основной набор должны попадать только принятые отношения. Отклонённые
сохраняются с причиной, спорные — в отдельной очереди. Ранее рассмотренные
пары переиспользуются по точному ключу с контрольной суммой снимка.
Проверки возвратных родителей выполняются отдельно: семантика не наследуется
от невозвратной пары автоматически. TODO по удалению Vся при наличии V пока
не применяется.

## Уже выполненный детерминированный аудит

Скрипт `scripts/audit_rule836.py` реализует подготовительную часть без новой
генерации: конкретное словарное соответствие, сравнение основы, конкуренция
родителей, качество лексического свидетельства и поисковые признаки толкований.
Сравнение основ намеренно консервативно; оно не заменяет полный анализ
преобразований и может пометить правильное чередование как требующее проверки.

| Очередь | Пар |
|---|---:|
| Неподтверждённое дополнительное изменение основы | 988 |
| Сохранённая основа, подтверждение цели только токеном Даля | 377 |
| Остальная семантическая проверка | 932 |
| Есть явное словарное соотв | 523 |
| Всего | 2820 |

Это непересекающиеся приоритеты, **не решения принять/отклонить**.
Всего дополнительное изменение основы отмечено у 1068 пар; у 80 из них
есть и прямое словарное соответствие. Этот результат ещё раз показывает,
почему нельзя просто удалить всю группу с изменённой основой.

Для 666 пар цель подтверждена только токеном Даля. В толкованиях 223 пар
найдены поисковые признаки одноактности/резкости, у 142 — признаки состояния.
Эти флаги пересекаются; ими нельзя подменить семантическую проверку.

Файлы:

- [Полная очередь 2820 пар](verb_rule836_filter_audit_2026.tsv).
- `docs/verb_rule836_filter_audit_2026.json` — статистика, контрольные суммы
  и крупнейшие группы конкурирующих родителей.
- `data/derived/verb_sfx.rule836.audit.jsonl` — подробные данные для будущих
  заданий LLM, включая толкования цели и возможные основы.

```sh
.venv/bin/python scripts/audit_rule836.py
```

Ни одна пара rule836 этим аудитом не принята и не удалена. Исходные кандидаты,
правила генерации и основной граф не изменялись. Полноценная семантическая
проверка rule836 — следующий этап, уже с подготовленной очередью и причинами
приоритета. Новая генерация для неё не требуется.
